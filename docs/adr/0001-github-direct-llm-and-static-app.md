# ADR 0001: GitHub直結LLM運用と完全静的Webアプリ構成

- 状態: 採用
- 日付: 2026-11-27

## 背景

GitHub Pages上で個人専用の楽曲分析データベースを長期運用するにあたり、LLMによる構造化登録・フィーリング推薦・MIDI生成をどのように組み込むかを決める必要があった。

## 決定

1. WebアプリからLLM APIおよびGitHub APIへ直接接続する機能を持たない。秘密情報であるAPIキーとトークンを一切アプリ側で扱わない。
2. 楽曲データの登録・更新、フィーリングからの作曲構成要素の提案、`MidiClip` JSONの生成・微調整は、GitHub連携済みのChatGPTがリポジトリを直接読み書きして実行する。
3. コンテキストを持たない新しいLLMセッションでも一貫した操作ができるよう、リポジトリルートに1ファイル完結の仕様書 `LLM_GUIDE.md` を配置する。
4. GitHub Pages上の静的Webアプリは、オフライン全文検索、同義語展開、度数進行検索、ブラウザ上でのMIDI再生と移調試聴、および `.mid` と `MidiClip` JSONの相互変換コピーと比較試聴に特化する。

## 影響

- セキュリティ面ではAPIキー漏洩やトークン管理の負担がなくなる。
- スキーマ変更時は `src/schema/` と同時に `LLM_GUIDE.md` を更新する運用規律が必要になる。
- GitHub Actionsで `validate:data` と Pages デプロイを自動化することで、ChatGPTからの直接コミットやPull Requestでもデータ破損を防げる。
